# PMX 汉化版 · 架构与设计系统文档

> 本文档定义本项目自 fork 后的模块划分与 GeekOS 设计系统规范。
> 所有新增/修改代码必须遵循本文档，避免"缝缝补补"式散落改动。

## 一、设计系统资源模块（GeekOS）

设计系统完全集中在下述资源文件中，**任何布局/主题/Java 代码都禁止硬编码颜色值**：

| 文件 | 职责 |
|---|---|
| `res/values/colors.xml` | 颜色 Token（**浅色 = 默认模式**），按 GeekOS 分层：基底层 / 品牌层 / 文字层 / 语义层 / 控件层 |
| `res/values-night/colors.xml` | 夜间模式覆盖值（仅覆盖与浅色不同的 Token） |
| `res/values/theme.xml` | `AppTheme`：windowBackground、双命名空间文字色桥接（`android:textColor*` 与 AppCompat `textColor*`）、对话框圆角/背景 |
| `res/values/styles.xml` | `BaseTheme`（品牌色 attr 绑定）、公共样式（按钮/分隔线） |
| `res/values/attrs.xml` | 主题自定义属性（accentColor 等）+ AppCompat 桥接属性声明 |
| `res/drawable/card_bg*.xml` | 卡片背景（圆角 + 弱边框），引用 Token 自动双模式 |
| `res/drawable/search_bg.xml`、`capsule_fill/outline.xml` | 搜索框 / 胶囊按钮背景 |

|---|---|---|
| windowBg | #F4F5F7 | #0A0A0F |

| cardBgPressed | #E9EBEE | #2A2A2F |

| 语义色 state* | 两模式相同 | 同左 |

### 双模式机制

- 主题 `Theme.AppCompat.DayNight` + `values/values-night` 资源覆盖 → 随系统/应用设置自动切换。
- 外观设置 → 夜间模式三档（跟随系统/浅色/深色）由 `BaseActivity.setNightTheme()` 应用。
- **新增颜色必须同时考虑两模式**：语义色/品牌色放 `values`；背景/文字类 Token 必须在 `values-night` 提供深色值。

## 二、Java 模块划分

```
com.mirfatif.permissionmanagerx
├── app/           应用入口（App）
├── base/          基础 Activity/Dialog（主题与夜间模式应用）
├── main/          主界面（应用列表）—— 卡片/密度/水波纹等外观一律通过 UiPrefUtils 读取
├── pkg/           单应用页（权限列表）
├── permview/      【新增模块】权限视图（按权限聚合）：PermListActivity + PermAppsActivity
│                  数据聚合层在 parser/PermListView（单例，随包列表刷新重建）
├── parser/        数据解析层：PackageParser / Permission / Package
│                  PermDescProvider【汉化模块】权限中文名+说明+规则翻译的唯一入口
├── privs/         守护进程交互（DaemonIface / DaemonHandler）
├── prefs/         设置（MySettings / SettingsFragTheme）
│                  appearance 相关开关值全部由 MySettings 暴露，UI 侧经 UiPrefUtils 消费
├── util/
│   └── UiPrefUtils 【外观模块】外观设置统一读取入口：
│        卡片背景/圆角档位、列表密度、水波纹、引用指示条、AppOp chip、大标题
│        各 Adapter 禁止直接散落开关判断
└── fwk/           系统兼容薄包装（*ActivityM）
```

### 模块规则

1. **外观**：任何界面要应用外观偏好，只允许调 `UiPrefUtils`，不允许在各处重复读取 SharedPreferences。
2. **颜色**：Java 侧取色统一用资源引用（如 `App.getCxt().getColor(R.color.stateRed)`），禁止硬编码 `Color.RED` 等做 UI 配色（文字高亮动态混合除外）。
3. **权限中文名/说明**：统一走 `PermDescProvider`（系统本地化名 → 内置映射 → 规则翻译三级兜底），其它代码不得自造映射。
4. **权限视图**：页面在 `permview` 包；聚合数据只由 `PermListView` 维护；权限修改后必须经 `PackageParser.updatePkgList()` 触发重解析刷新。

## 三、历史遗留修复记录（与审查报告联动）

- M1 权限视图刷新：`PermAppsActivity` 观察 `getPkgListLive()`，修改后 `updatePkgList()`。
- M2' 批量假成功：`batch()/setEntry()` 先 `DaemonHandler.isDaemonAlive()`。
- 深色底黑字：曾因颜色全局硬编码深色导致浅色模式黑字不可见，已由"浅色默认 + values-night 覆盖"的 Token 双模式方案根治。
